# Provenance of `chaos_data_with_efa_deed.xlsx`

This procedure describes the historical files of the EFA merge, not a corrected reanalysis. The original MATLAB programs are preserved alongside this note as `extract_element.m` and `merge_efa_deed_data.m`. The independent, read-only verification program is `build_efa_provenance_data.py`; it is **not** the historical creation script. No original workbook was edited.

## Source chain and reproducible historical steps

1. `data_1002_delete_cf88_227.xlsx` has 503 prepared `cF8_225` material rows. Its `DFT_properties` and `ele_descriptors` sheets are aligned by material `name` and row order. The original upstream export/query and rule selecting these 503 records are not present in this folder; the filename alone does not establish either.
2. Run `extract_element.m` in MATLAB with that workbook in the working directory. It reads `DFT_properties!A2:A10000`, takes the text preceding `:PAW_PBE`, extracts element symbols, removes oxygen, and writes **only the first four metal symbols** to `extracted_metals.xlsx` as `Metal1` through `Metal4`. A fifth cation, if present, is discarded from these join columns.
3. `chaos_data.xlsx`, `Sheet1`, combines the aligned `name`, four extracted metals, seven DFT-property columns and 25 element-descriptor columns. The original script/notebook performing this assembly is **not** in this directory. Direct cell-by-cell checks establish that all 503 names and four-metal rows match their sources, and that all 16,096 retained DFT/descriptor cells match the prepared workbook. This establishes the data relationship, not a missing historical command.
4. `lib5_organized_072125.json` contains 529 four-cation EFA records. `lib5_efa_deed.xlsx` has corresponding 529-row `raw` and `cleaned` sheets. The `cleaned` sheet holds Metal1–Metal4 in columns A–D and `EFA` in column E, followed by fields the manuscript does not use, which the deposited copy, `analysis/00_cohort_lock/input/lib5_efa_deed_source.xlsx`, omits. That copy keeps only the 493 systems of the cohort, so row numbers such as `efa_original_row` refer to the original 529-row sheets. JSON and workbook records agree by order and numerical precision. The original JSON-to-Excel conversion procedure is absent.
5. Run `merge_efa_deed_data.m` in MATLAB with `chaos_data.xlsx` and `lib5_efa_deed.xlsx` in the working directory. It prefers the `cleaned` sheet, falling back to `raw`. For each `chaos_data` row, it sorts nonempty `Metal1`–`Metal4` (`B:E`) and compares them with the sorted four metals in `cleaned!A:D`. It uses the **first** match, writes the `cleaned` fields from column E onward to the output from column `AL`, the one-based source Excel row to `efa_original_row`, and the number of matches to `match_count`. It drops unmatched rows and writes `chaos_data_with_efa_deed.xlsx`. The script specifies output sheet `Sheet1`; the surviving workbook has sheet `combined`. The rename is not documented, but the 503 data rows agree with the script's intended output, and every stored match points to the recorded source row.

To reproduce the **historical** workbook, run the two original MATLAB scripts in this order after providing the already-prepared `chaos_data.xlsx` and `lib5_efa_deed.xlsx`. The absent assembly and JSON-conversion steps cannot be exactly replayed from code in this folder. Do not use this historical merge to construct corrected five-cation EFA values; it contains the error described in `JOIN_DIAGNOSIS_CONFIRMED_20260925.md`.

## Cohort and identifiers

The prepared input has 503 rows. All 503 find one four-metal source key (`match_count=1`). Of these, 493 have four cations in the full POCC material name with 0.25 occupancy per cation; ten have five cations with 0.2 occupancy per cation. Thus the **493-row four-cation cohort** is obtained by selecting the four-cation rows from the prepared 503 after the historical merge. There is no additional filter for these 493 in either surviving script. The upstream reason for selecting the prepared 503 from a larger CHAOS database is not recoverable here.

The accompanying Excel file, `chaos_efa_provenance_493_rows.xlsx`, maps each of the 493 rows to its full POCC `name`, four-metal key, source-workbook row, JSON record position, and `chem_id`. The full `name` is a POCC record identifier available in these files, **not a verified AUID**. No AUID column or AUID crosswalk is present in the eight local files. Mapping to actual AUIDs requires the database export or its owner.

No file contains a verified database snapshot timestamp or export date. In particular, `072125` in a JSON filename and filesystem modification times are not accepted as a database export date. This is explicitly marked “not recorded” in the workbook.

The JSON records contain a configuration count (`dg_len`) but no flag for complete, preliminary, unpublished, or incomplete POCC ensembles. Thirty-eight of the 493 cohort rows have counts below the modal count of 18 and are flagged for review in the workbook. **A count below 18 does not prove incompleteness**; all 493 publication/completeness states remain unverified. A database-side ensemble-status export is needed to resolve this advisor request.

## Verification and limitations

`build_efa_provenance_data.py` checks every one of the 503 prepared and merged rows against the historical sources, then emits the audit data used for the Excel mapping. It verifies 503/503 aligned names, four-metal rows and preserved input rows, 16,096/16,096 retained source descriptor cells, and 503/503 EFA source-row matches. It finds 493 unique four-cation matches, ten five-cation parent collisions, and 36 unused records among the 529 four-cation EFA records. These checks establish lineage **within this directory**. They do not supply missing AUIDs, export dates, ensemble statuses, or correct five-cation EFA values.
